Enterprise Brain

Two Mission Controls, one governed ledger

An employee runs a fleet of agents and keeps a private board. The platform team governs the agents the enterprise itself runs and keeps a review queue. They share exactly one ledger, and one interface between the boards: a request out, a decision back.

Everything in the seeded world is fictional. Alice, Bob, Carol and Dave are placeholder identities and every figure is invented. No real person, system of record or internal number appears anywhere in it.

Local demo host. The token list below exists only because this process was started with --seed. A real deployment never returns a bearer value from an endpoint.

What the ledger enforces

  • Scope is computed, never declared. A derived output's audience is the intersection of its inputs' audiences, so restricted data cannot be widened by the agent that derived it.
  • Corrections cascade. Superseding or tombstoning an output marks everything built on it stale, immediately.
  • A harness source floors the scope at the producing fleet, because an intersection over the employee's own mail would be unbounded rather than narrow.
  • Status comes from a check that can fail, never from the producer's claim. No gate for a kind means unverified, which is not the same as fine.
  • Conflicts are surfaced, never resolved. Two live answers that disagree are both returned with their provenance.

What the host enforces

  • Identity comes from the token. The employee and the fleet are read from it; a body that names either is acting as itself.
  • Only the agent id comes from the request, and it is checked against the roster, or a fleet could borrow another agent's grant.
  • The gateway is the only enforcement that counts. Every access decision is re-evaluated on every call.
  • Every vendor write terminates at a human. That is the break in the chain from hostile content to a system of record.
  • No entitlement is stored here. They resolve against the directory on every call, so offboarding needs no cleanup job.
