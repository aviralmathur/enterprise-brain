# Routing — work → lane

The **only** place work-to-lane mapping is written. If a charter also routes, delete it
there. Check the confusable-pairs list *before* deciding a lane — that is where two agents
quietly duplicate each other.

## The table

| The work | The lane |
|---|---|
| A durable, reusable product | Product agent |
| A client-specific demo or pursuit artifact | Pipeline / delivery agent |
| A deck, one-pager, positioning | Collateral agent |
| Licences, access, keys, environments | IT / tooling agent |
| Outbound business development | BD agent |
| "Where does this go bigger", bets, kill/park calls | Strategy agent |
| Friction inside *our own* process | Inward-facing agent |
| Inbox / brief / triage / "what did I miss" | Chief-of-staff orchestrator |
| **Anything else** | **Chief-of-staff orchestrator** |

## Confusable pairs — write the boundary down, with an example of each mistake

Every fleet grows two or three boundaries that look alike and are not. Undocumented, the
pair duplicates each other for months. Name them here.

- **Product vs Pipeline.** Durable reusable thing → Product. Client-specific one-off →
  Pipeline. *Mistake A: a reusable engine built inside a client demo and never harvested.
  Mistake B: a bespoke pursuit hardened into "the product".*
- **Strategy vs Inward-facing.** "Where does this go bigger" → Strategy. "This step in our
  own process is broken" → Inward-facing. *Mistake: routing a process-friction gripe to
  Strategy, which dreams instead of fixing.*
- **BD vs Collateral.** The outbound pursuit itself → BD. The deck it carries → Collateral.
  *Mistake: BD writing the positioning deck from scratch instead of asking Collateral.*

Add your own pair the first time two agents collide.
